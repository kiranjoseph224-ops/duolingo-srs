# Duolingo — Software Requirements Specification

## Overview
Produced a 50-page Software Requirements Specification for Duolingo as part of a team of 6, following IEEE 830 standards. The document covered stakeholder analysis, goal modelling, use cases, domain modelling and quality requirements.

## My Role
**Requirements Analyst (15% contribution)**

- Created the Stakeholder Matrix and accompanying analysis, covering 15+ stakeholder groups
- Authored Section 2.2 on Product Functions
- Developed the Non-Functional Requirements, including reliability, performance, security and usability
- Contributed to the Domain Model

## Technologies & Standards Used
- IEEE 830-1998 Standards
- KAOS Goal Modelling
- UML Use Case Diagrams
- Domain Modelling
- Non-Functional Requirements Analysis

## Key Contributions
- Stakeholder Matrix mapping 15+ groups including free learners, paid learners, teachers, parents, developers, data scientists, and external partners
- Product Functions section defining core system capabilities
- Non-Functional Requirements covering:
  - Reliability: 99.5% monthly uptime, crash rate under 0.1% per 1,000 sessions
  - Performance: lesson load within 2 seconds, API response within 500ms
  - Security: AES-256 encryption at rest, TLS 1.3 in transit, annual penetration testing, 14-day critical vulnerability remediation
  - Usability: WCAG 2.1 AA compliance, reduced cognitive load in child mode
  - Scalability: support for 3x normal load with no more than 20% performance degradation
